# 网页召回、索引互补与 SWE‑2 协议续轮复测

## 公网搜索

FRAMES 连续 12 题，前 6 题用于定位漏召回，后 6 题是未参与调优的留出集。每题的各执行器收到完全相同的一条查询。只测前十条结果中的官方 Wikipedia 证据，不代表多轮网页任务的答案正确率。

| 方案 | 前 6 题证据 / 20 | P50 | 留出集证据 / 29 | P50 |
|---|---:|---:|---:|---:|
| 改前内置 | 1 | 4.00 s | 0 | 4.00 s |
| 改后内置（参考源补查 + 标题排序） | 4 | 4.00 s | 2 | 4.00 s |
| Exa 匿名 MCP | 5 | 1.21 s | 5 | 1.32 s |
| 本机 SearXNG | 2 | 1.29 s | 2 | 1.03 s |

SearXNG 固定提交 `c6ee3e9fd0235004a694e63720efc869bb1e3594`，启用 Google、Bing、Brave 和 Wikipedia 列表，不用公用实例。Brave 限流，其他源仍有返回；结果不是所有部署的上限。匿名 Exa 本次 12/12 返回；此前曾观察到初始化 HTTP 403。匿名服务不作为强制默认，用户可在 Cursor MCP 中按需启用。

事后把 Exa 与改后内置的结果交错合并、去重并保留前十条，12 题覆盖由 Exa 单独的 10/49 变为 11/49；不限制数量的并集合计 12/49。它说明两个来源能补漏，不代表默认并发双发比按需调用更划算。

## 代码索引、语义和符号

同一份公开 RepoQA 六仓库、60 自然语言题 + 60 精确函数名题，命中以结果区间是否覆盖官方标注的函数定义行为准。Python Semble MCP 和 Serena 是当前实际注册的服务，Rust 为单独的索引核心基准，未接进工作区扩展。

真实 Semble MCP 的热查 P50 为自然语言 2.00 ms、精确函数名 2.34 ms。Serena 通过了定义、引用、实现、未知符号和重启回归；它和函数名候选排名不是同一指标。Semble 的分支切换与重启用例也通过。未跑 Claude Code 或 Cursor 官方同题，不作超越声明。

Rust 和实际 Semble MCP 在自然语言前十各独有 7 个命中，候选并集覆盖 33/60。预算仍限制前十时，简单交错仍是 26/60；前五小幅提高到 22/60。函数名交错为前五 51/60、前十 53/60。先保留 Serena 作为定义、引用和实现的权威；Rust 适合低延迟候选和补漏，现有证据不支持直接全量双索引或用 Rust 无条件替换 Semble。

## SWE‑2 长对话通过真实 BYOK 适配器

同一模型 `devin/swe-2`、同一个本机 Magpie、同样的 3 个真实公开仓库任务（Black #0、Tracing #1、fzf #0）。每个协议每仓库跑 5 个流式请求：先由模型发起一次 `read_public_source`，回填 19–24 万字符带行号的公开源码，再跑 3 个追加核验轮。共 45 次调用，9 次工具请求、9 次首次源码注入、27 次已预热续轮。调用经过 BYOK 三个生产协议适配器，不经过 Cursor IDE 的实际 checkpoint 或 compaction 链路。

| 协议 | 首次源码注入缓存占比 | 稳定续轮缓存占比 | 稳定续轮达 95% | 首段正文 P50 |
|---|---:|---:|---:|---:|
| Messages | 0.38% | 99.83% | 9/9 | 1.62 s |
| Chat Completions | 1.24% | 99.75% | 9/9 | 1.79 s |
| Responses | 1.24% | 99.83% | 9/9 | 1.37 s |

百分比以 `Σ cache_read / Σ context_input` 计算，同一续轮有约 53K–88K 输入。首次回填的大段源码是新输入，不应与稳定续轮混算；语义任务正确率也独立计分，三个协议的稳定续轮均为 6/9 正确。当前数据支持「稳定长前缀可以高命中」，不支持全场景 95% 或不同模型使用同一缓存策略。

适配原则：共享层保证旧消息、MCP 目录和工具顺序不被改写。协议层分别维护 Messages 缓存断点、Chat 用量回执、Responses replay 及缓存字段。只有同模型、同协议、同一工作负载的对照找出具体问题，再加模型特例，不给 SWE‑2 一律套 GPT 或 Claude 的策略。
